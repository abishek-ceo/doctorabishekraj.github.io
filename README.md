# Abishek Hospital website: abishekhospital.com

Fast, mobile-first, multi-page static website for **Abishek Hospital, Erode Fort** (Dr. Jayanthi Prabakaran).
Hosted on GitHub Pages from the `main` branch; the custom domain is set by the `CNAME` file (never delete it).

## How it is organised

| Path | What it is |
|---|---|
| `index.html`, `*/index.html`, `404.html`, `privacy-policy.html` | **Generated pages.** Do not edit by hand; they are overwritten by the builder. |
| `tools/site.mjs` | Hospital facts (address, phone, clinic hours, social links, stats, service list). Change a fact here once and it updates everywhere. |
| `tools/pages/*.mjs` | The words on each page (home, service pages, doctor, videos, contact, FAQ, gallery, privacy, and the two patient tools in `tools.mjs`). |
| `tools/pages/regions.mjs` | The Tamil Nadu pages: the hub `/womens-hospital-tamil-nadu/`, one page per nearby town (`districts` in `tools/site.mjs`) and the Tamil-language page `/ta/`. |
| `tools/lib.mjs` | Shared header, footer, buttons, SEO tags and structured data (JSON-LD). |
| `assets/css/site.css`, `assets/js/site.js`, `assets/js/tools.js` | Styling and the tiny scripts: `site.js` (menu, map, video, WhatsApp booking form, count-up numbers) runs on every page; `tools.js` (due-date calculator, visit reminder) loads only on the two tool pages. |
| `doctor.png`, `hospital-logo.png` | Original brand images. The previous site used them as its share image and logo, so other sites may still link to them: keep them. `doctor.png` is also the source for the portrait made by `tools/make-images.py`. |
| `assets/fonts`, `assets/img` | Self-hosted fonts and optimised images (generated by `tools/make-images.py`). |
| `sitemap.xml`, `robots.txt`, `assets/icons.svg` | Generated by the builder. |
| `sw.js` | Intentionally a **self-removing service worker**. An early version of the site cached pages forever; this file cleans that up for old visitors. Keep it. |

## Everyday commands

```bash
node tools/build.mjs     # regenerate all pages, sitemap and icon sprite (Node 18+, no dependencies)
node tools/check.mjs     # verify links, anchors, icons, JSON-LD, titles/descriptions, sitemap
```

Typical edit: change the text in `tools/pages/...`, run the two commands above, commit everything (generated files included), merge to `main`.

## Hospital photos

1. Put your own photos (jpg/png/webp) in a `photos/` folder. Use the **original full-size files** (ideally 1600 px or wider); small Google Maps thumbnails look blurry. Photos are shown at their natural size. Avoid patients and newborns unless you hold written consent.
2. `python3 tools/make-images.py` (needs Pillow, numpy, scipy). It resizes to 480/960/1600 px WebP and strips location data (EXIF/GPS).
3. Add a line per photo in `photos/captions.json`: `{"file-name-without-extension": {"alt": "...", "caption": "...", "order": 1}}`.
4. Run the build. A Gallery page, menu entry and a home-page photo strip appear automatically when photos exist.

## Notes

- A click-to-enlarge photo viewer existed until commit `186f005`; it was removed because the current photos are too small to enlarge. Restore it from that commit if full-size photos arrive.
- `node tools/check.mjs` also fails if an image, font or script in `assets/` is not used by any page, stylesheet or the manifest, so leftovers are caught early.
- The "Write a Google review" links use `reviews` in `tools/site.mjs`.
- **Patient tools:** `/pregnancy-due-date-calculator/` (indexed) and `/visit-reminder/` (not indexed, not in the sitemap). Both run in the visitor's browser and nothing typed in is sent or stored. On the reminder page, staff can fill in the date and time and tap "Send on WhatsApp": the link carries only the date, time and visit type, and opens pre-filled on the patient's phone. Clinic hours come from `hours` in `tools/site.mjs`.
- **Open now line:** the home and contact pages show "Open now · 24/7" (`statusLine` in `tools/lib.mjs`). It is plain text, not a live clock, because the hospital is open round the clock. The separate "Clinic hours" (Mon – Sat, 9:00 AM – 6:30 PM) shown on the contact page, in the footer and in the FAQs are unchanged.
- **Speed and motion:** browsers that support it fetch a page when its link is hovered or pressed (speculation rules in `tools/lib.mjs`) and fade between pages (cross-document View Transitions, CSS). Cards and headings fade up once as they scroll into view, and the experience-band numbers count up (both in `site.js`, using IntersectionObserver; only items below the fold are touched, so nothing stays hidden if the script fails). The hero entrance, floating badge, pulsing dots, FAQ slide-open and press feedback are CSS. All CSS movement sits in one block of `site.css` (`motion`) that is switched off for visitors who ask their device for reduced motion and when printing. There is deliberately no scroll-linked animation (a reading-progress line was removed after it stuck on an iPad). Keep new moving parts inside that block. New CSS such as `@view-transition` is valid but unknown to the W3C CSS validator, so it reports it; the page HTML validates cleanly.
- **Tamil pages:** `/ta/` plus Tamil versions of the seven service pages (`/ta/<service slug>/`, in `tools/pages/ta-services.mjs`) and three guides (`tools/pages/guides.mjs`). A "தமிழ்" / "English" button in the header (and menu) switches to the matching translation; the pairs point at each other with `hreflang`, also in `sitemap.xml`. The Tamil text needs a native-speaker proofread. Keep the English and Tamil facts in step.
- **Search Console / Bing:** after you add the site in Google Search Console, paste the `content` value of its HTML-tag verification into `verification.google` in `tools/site.mjs` (and Bing's into `verification.bing`), rebuild and publish, then press Verify and submit `https://abishekhospital.com/sitemap.xml`.
- **Warm touches:** a kolam-inspired pattern (inline SVG, so it is never counted as the page's largest paint), a Tamil welcome line, drifting petals and soft hover effects. They sit with the other motion in `site.css` and are switched off for reduced motion.
- **Tamil Nadu search pages:** we have ONE hospital, so these pages say how far Erode is from each town and how to get here; they must never claim a branch elsewhere. Add a town only with real travel information, in `districts` in `tools/site.mjs` (`km` is a rounded road distance from public maps). The English home page and `/ta/` point at each other with `hreflang`. The Tamil text should be proofread by a native speaker. No page can be guaranteed a Google ranking.
- **Browser support and layout rules:** built for iOS 14.5+/Safari 14.1+, Chrome and Android WebView 84+, Samsung Internet 14+, Firefox 78+ and Edge 85+ (the JavaScript is plain ES5). Older phones still show all content, but flex `gap` spacing is missing before those versions. It was tested in real WebKit (WebKitGTK), Chromium at 27 phone/tablet/desktop sizes, with text enlarged to 200%, with JavaScript off, in high-contrast and dark mode. Keep these rules so it stays that way: single-column grids use `minmax(0,1fr)` (never plain `1fr`, or one long word widens the whole column); headings and body text may wrap anywhere (`overflow-wrap:anywhere`) so a long Tamil word never pushes the page sideways; touch targets are at least 44px tall; the page declares `color-scheme: light` so phone dark modes do not recolour it. Firefox itself and real iPhones/iPads could not be tested here.
- **Search result titles:** keep every `title` under about 580px wide (roughly 60 English characters, about 45 Tamil ones, since Tamil letters are wider) or Google cuts it off; descriptions under about 155 characters. Tamil pages end with the short brand "அபிஷேக்" to fit. Do not add unverified claims to the structured data (the old `priceRange` was removed). FAQ markup is kept for assistants and accessibility, but Google only shows FAQ dropdowns for government and health-authority sites, so do not expect them.
- **Menu breakpoint:** the full menu shows from 1160px wide; below that (phones, iPads, small laptops) there is the menu button and the Call/WhatsApp/Directions dock. At 1024-1159px the full menu overlapped the hospital name, so the breakpoint lives in `site.css` (three places) and `site.js` (`matchMedia`).
- **Phone action bar:** the floating Call / WhatsApp / Directions bar hides itself while the page's own hero Call and WhatsApp buttons are on screen (it would sit on top of them and repeat them) and returns once they scroll away (`mbar-off`, in `site.js`). Pages with no hero button row keep it showing.
- **Share links:** each guide ends with a "Share on WhatsApp" link (`shareRow` in `tools/lib.mjs`), a plain link with no script.
- No cookies, analytics or third-party scripts load by default. Google Maps loads only after a visitor taps "Show map".
- The booking form opens WhatsApp (or email) with the details pre-filled; nothing is stored on the website.
- Add another social profile in `tools/site.mjs` (`social`) and add its icon to `tools/icons.json` if needed.
- `assets/img/og-image.jpg` is the WhatsApp/Facebook share preview; its template is `tools/og-template.html`.
- Videos use a click-to-play card (nothing loads from YouTube until it is tapped). The embedded video is `featuredVideo` in `tools/site.mjs`; only add video IDs that are confirmed to be on the hospital's own channel, then run the build.
